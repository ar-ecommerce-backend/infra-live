# infra-live

Terraform for running the ar-ecommerce-backend on AWS (us-east-2), plus the GitHub
Actions that create it, test it, and tear it down.

```
https://ar-ecommerce-backend.com ──► Load Balancer ──► api-gateway ──► 8 services (Eureka) ──► RDS Postgres
               (443, TLS 1.2+)               (ECS Fargate Spot, one task each)      (one DB per service)
```

- **ECS Fargate (Spot)** runs each service's public GHCR image; config-server is left out
  (every service imports it as optional, see docs ADR 0004).
- **HTTPS only.** Free ACM certificate (in `bootstrap/`, renewed by AWS); port 80 just redirects to 443.
- **Only the load balancer is public.** Security groups let it reach the gateway alone;
  services talk to each other inside one group; Postgres accepts only the services.
- **Secrets** (DB password, JWT signing key) are generated by Terraform, stored in SSM
  Parameter Store and injected into containers. They never appear in code or logs.
- **No stored AWS keys anywhere.** GitHub Actions gets short-lived credentials via OIDC,
  and only for workflows on this repo's `main` branch.

## Cost control

It is built to be switched on for demos and deleted afterwards.

| | |
|---|---|
| Running | ~$0.15–0.25/hour (9 Spot tasks, load balancer, db.t4g.micro, public IPs) |
| Deleted | ~$0 (state bucket only) |
| Guard 1 | **Auto-down timer**: every "up" starts a 4-hour timer that runs "down" (a new "up" restarts it) |
| Guard 1b | **Auto-shutdown**: hourly backup check, destroys the stack once older than 4 hours (GitHub may run it late) |
| Guard 2 | **$20/month budget** (in `bootstrap/`) emails at 50%, 75%, 100% and when the forecast passes it |

## Layout

| Path | What | Applied by |
|---|---|---|
| `bootstrap/` | State bucket + GitHub OIDC provider and deploy role | You, once, from a laptop |
| `aws/` | Network, database, ECS services, load balancer | The **Demo environment** workflow |
| `.github/workflows/demo.yml` | `up`: apply + E2E suite against the live URL. `down`: destroy | Manual (Actions tab) |
| `.github/workflows/auto-down-timer.yml` | Waits 4 hours after an "up", then runs "down" | Started by "up" |
| `.github/workflows/auto-shutdown.yml` | Destroys the stack once it is older than 4 hours | Hourly schedule |

## One-time setup

```bash
aws login --profile ecom
eval "$(aws configure export-credentials --profile ecom --format env)"
cd bootstrap && terraform init && terraform apply
```

Then store the two outputs as repository **variables** (not secrets, nothing here is
sensitive): `TF_STATE_BUCKET` and `AWS_DEPLOY_ROLE_ARN`.

```bash
gh variable set TF_STATE_BUCKET --body "$(terraform output -raw state_bucket)"
gh variable set AWS_DEPLOY_ROLE_ARN --body "$(terraform output -raw deploy_role_arn)"
```

## Day to day

Actions → **Demo environment** → Run workflow → `up` (or `down`). The run summary shows
the live URL once the E2E suite has passed against it.

Running Terraform for `aws/` locally works too:

```bash
eval "$(aws configure export-credentials --profile ecom --format env)"
cd aws && terraform init -backend-config="bucket=<TF_STATE_BUCKET>" && terraform plan
```
